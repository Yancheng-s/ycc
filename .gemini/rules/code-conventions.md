# 编码与生成约束

- **不生成解释性注释**：代码需具备自解释性，禁止在常规业务或执行逻辑中添加描述“代码在做什么”的解释性注释。
- **禁止使用 `??` 兜底**：禁止使用空值合并运算符（`??`）做隐式兜底掩盖潜在未定义行为，缺失或异常值必须通过前置校验、类型守卫或显式异常处理解决。

# 代码质量与门禁约束

- **类型检查强卡点**：所有代码必须 100% 通过 TypeScript 严格类型检查（`npm run typecheck`），严禁存在任何类型隐患或类型逃逸。
- **规范自动化拦截**：禁止 `??` 兜底与冗余注释的约束必须由自动化脚本静态拦截，违规直接中断测试与构建。
- **统一质量门禁（check）**：建立统一的质量门禁入口（类型检查 + 规范静态扫描 + 单元测试），任何变更后必须全绿通过方可视为完成。

# 测试约束

- **功能与测试同步联动**：只要涉及功能模块的新增、重构或行为调整，必须同步编写或修改对应的测试用例，严禁业务代码单边演进。
- **全量回归验证**：每次代码变更后必须执行全量自动化门禁验证，确保全局用例 100% 变绿通过，零回归退化。

# 架构与文档资产全生命周期治理约束

文档与代码具备完全平等的生命周期地位，必须遵循以下治理规范：

- **新模块诞生（Create）**：当系统引入全新的核心能力或独立模块时，必须在 `docs/` 目录下按序号新建对应的技术设计文档（`docs/0X-xxx.md`），明确其设计范式、契约定义并绘制专有架构图；同时必须在 `docs/README.md` 的索引表中登记，并在系统全景拓扑图中补充该节点与调用链路。
- **模块调整与重构（Refactor / Restructure）**：当单文件升级为独立目录、模块职责拆分、依赖关系重组或生命周期迁移时，必须同步重构对应的文档结构与 Mermaid 图，修正 `docs/README.md` 中的系统全景依赖连线，严禁残留与真实代码脱节的过时调用图。
- **已有模块演进（Update）**：模块内部逻辑增强、参数调整或行为微调时，必须同步刷新对应文档的实现细节与时序图，保证说明真实准确。
- **里程碑进度同步归档**：任何演进阶段达成或重大结构拆解完成，必须同步更新 `.gemini/roadmap.md`。

# 研发流程与自动审计规范

.gemini 下的规则作为全局基准规范一次性确立，后续日常开发严格遵循以下机制：
- **常规小改动**：轻量直接修改，保持高效敏捷。
- **涉及功能、模块、核心流程的变动**：
  在代码与测试生成完成后，**必须自动触发全量审计**：
  1. **静态类型审计**：运行 `npm run typecheck`，确保 TypeScript 严格模式下 0 报错。
  2. **契约测试审计**：运行 `npm test`，确保全量自动化测试用例 100% 通过，无回归缺陷。
  3. **规范合规自审**：严格审查生成代码与测试，确保无解释性注释、无 `??` 运算符隐式兜底。
  4. **文档资产审计**：核对 `docs/` 是否已完成“新建文档/调整结构/刷新图表/注册索引”全生命周期同步，`.gemini/roadmap.md` 是否已归档。
  5. **审计报告输出**：汇总审计结果向用户交代，确保每次交付高质量闭环。

# 01 - 加尔定律与系统自然生长法则

## 一、 核心设计哲学

### 1. 加尔定律（Gall's Law）
> **“所有能正常运行的复杂系统，必然是从一个能够运行的简单系统演变而来的；从零开始设计的复杂系统，从来都无法运行，也无法通过打补丁使其运行。”**

在构建 AI Agent 这种高度动态、不可控的系统中，最忌讳的是在没有任何业务跑通前，就根据设想预先创建大量空桩目录（如 `services/`、`repositories/`、`interceptors/`、`decorators/`）。这种过早设计不仅增加了心智负担，更掩盖了真实的调用链路。

### 2. 避免过度设计（Anti-Over-Engineering）
系统的复杂度必须由**真实的业务痛点**驱动，而不是凭空设想。每一次抽象，都必须建立在前一阶段代码已经变臃肿、出现职责混乱的临界点上。

## 二、 系统自然生长的 5 阶段演进模型

```mermaid
flowchart LR
    P1["阶段 1: 极简单文件 MVP<br/>(跑通单轮问答闭环)"] --> P2["阶段 2: 注入核心能力<br/>(多轮记忆 / 工具调度 / 超时保护)"]
    P2 --> P3["阶段 3: 内核扁平拆分<br/>(单一职责独立单文件)"]
    P3 --> P4["阶段 4: Hook 管道解耦<br/>(纯净内核 / 空对象分发器)"]
    P4 --> P5["阶段 5: 业务目录封装<br/>(复杂度上升后模块化成目录)"]
```

| 演进阶段 | 驱动力与重构信号 | 架构形态 | 产出物标准 |
| :--- | :--- | :--- | :--- |
| **阶段 1：极简单文件 MVP** | 验证大模型通信可行性 | 单个 `main.ts` 文件，少于 30 行 | 跑通最小调用闭环 |
| **阶段 2：注入核心能力** | 赋予 Agent 记忆与动手能力 | 在单文件中引入记忆队列与受控循环 | 跑通 `tool_calls` 执行闭环 |
| **阶段 3：内核扁平拆分** | 单文件代码超 100 行，职责混杂 | 拆分为多个平级单文件（`types` / `client` / `agent` / `tools` / `cli`） | 消除启动入口与调度入侵 |
| **阶段 4：Hook 管道解耦** | `console.log` 和条件判断污染内核 | 抽象 `AgentHooks` 与 `HookDispatcher`，内核零 I/O 副作用 | 实现可观测性与核心逻辑完全解耦 |
| **阶段 5：业务目录封装** | 某个单文件行数剧增、内含多重子逻辑 | 将单文件升级为独立目录（如 `src/tools/` 下多文件并由 `index.ts` 导出） | 保持对外契约完全稳定不变 |
